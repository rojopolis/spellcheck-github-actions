# Release 1.0.0 + Build Script Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `1.0.0` as a stability-milestone release (no functional change to the action) and harden `scripts/build.pl` so DockerHub publishing fails loudly on error, correctly supports independent floating major-version tags (`v0`, `v1`, `v2`, …) including security backports to older majors, and never regresses the `latest` Docker tag to an older major.

**Architecture:** `scripts/build.pl` is refactored from one linear imperative script into small, pure, independently-testable subroutines (version parsing/comparison, tag-name derivation, target-list decision, checked command execution) plus a thin `main()` that wires them together and does the actual `docker`/`git`/`gh` calls. The pure decision logic gets unit tests in a new `t/build.t`; the external-service glue (DockerHub auth, registry verification) gets a documented manual dry-run since it talks to a live, credentialed, external service that isn't mocked anywhere else in this codebase.

**Tech Stack:** Perl (`autodie`, core `version` module, core `Test::More`, core `File::Temp`/`Cwd` for tests), `git`, `docker` + `docker buildx`, `gh` CLI.

**Spec:** This plan's spec is the conversation it came from (no separate design-doc file was written; the short design was approved inline). Key decisions, verbatim from that conversation:

- DockerHub publishing stays local/manual — the maintainer has `push`, not `admin`, on the upstream repo (verified via `gh api repos/rojopolis/spellcheck-github-actions --jq '.permissions'`), so repo secrets can't be added, and even if they could, exposing a personal-namespace DockerHub credential to a repo the maintainer doesn't own is a real exposure.
- The floating tag must be derived from the version being released (`v$major`), not hardcoded `v0`, so each major line's tag moves independently — this is what makes backporting a security fix to an old major safe.
- `latest` must only ever point at the highest version across *all* majors — a backport release to an older major must never become `latest`.
- No change to the action's actual inputs/behavior; this is a stability-signal release.

## Global Constraints

- No new non-core Perl dependencies (use `version`, `Test::More`, `File::Temp`, `Cwd` — all core).
- Keep `system()` calls in string form (shell-interpolated), matching the existing script's style — `$VERSION` originates from the maintainer's own CLI argument, not untrusted input, so there's no injection concern that would justify a list-form rewrite.
- `scripts/build.pl` must remain runnable exactly as today: `perl scripts/build.pl <version>`.
- Do not touch `.github/workflows/docker-build.yml` (GHCR path) — out of scope.
- `v0` must keep pointing at the latest `0.x.x` release and must never move to `1.x.x` or later.
- Perlcritic policy `InputOutput::RequireCheckedSyscalls` (`.perlcriticrc`, `functions = :builtins`) applies — every remaining bare `system()`/`qx{}` call site must have its result checked or be wrapped by a sub that does.

## Review Focus

- A version string that doesn't match `major.minor.patch` (typo, stray pre-release suffix) must fail with a clear message before any Docker/git work starts, not produce a nonsensical floating tag or a confusing `version->parse` error. (Task 1)
- Releasing the very first version of a brand-new major (e.g. a future `2.0.0`) must not die trying to delete a `v2` tag that doesn't exist yet, locally or remotely. (Task 3)
- A backport to a major that is neither the oldest nor the newest (e.g. `1.5.0` released after `2.0.0` already exists) must still only move `v1`, and must not become `latest` — the logic must generalize past the two-major (`v0`/`v1`) case discussed. (Task 1)
- Re-running the release for the *current* latest version (idempotent re-release, e.g. a failed push retried) must still correctly count as `latest`, not be excluded because it "already exists" in the tag list. (Task 1)
- `docker buildx imagetools inspect`, used for post-push registry verification, requires the Buildx plugin; if it's missing the script must say so clearly during preflight, not fail obscurely mid-release. (Task 5)

### Task 1: Version parsing, comparison, and target-list decision logic

**Files:**

- Modify: `scripts/build.pl` (new subs, placed after the `use` statements and before the current top-level script logic)
- Create: `t/build.t`

**Interfaces:**

- Produces: `validate_version_format($version)` — dies with a clear message unless `$version` matches `^\d+\.\d+\.\d+$`; returns `$version` otherwise.
- Produces: `major_version($version)` — returns the major component as a string (e.g. `'1'` for `'1.0.0'`).
- Produces: `floating_tag_name($version)` — returns `"v" . major_version($version)` (e.g. `'v1'`).
- Produces: `existing_release_tags(@tags)` — returns the subset of `@tags` matching `^\d+\.\d+\.\d+$` (filters out floating tags like `v0`, `v1`, and non-release tags like `latest`).
- Produces: `is_new_latest($candidate, @existing_tags)` — returns true iff `$candidate`'s version is `>=` every tag in `@existing_tags`, comparing with the core `version` module. `@existing_tags` need not include `$candidate` itself.
- Produces: `targets_for($version, @all_tags)` — returns the ordered list of Docker tags to build/push for this release: `($version, floating_tag_name($version))`, plus `'latest'` appended iff `is_new_latest($version, existing_release_tags(@all_tags))` is true. `@all_tags` is the raw, unfiltered tag list (as `git tag --list` would return).

- [ ] **Step 3: Implement `run_or_die($cmd)` in `scripts/build.pl`**

```perl
sub run_or_die {
    my ($cmd) = @_;
    say $cmd;
    system($cmd);
    if ($? == -1) {
        die "Failed to execute '$cmd': $!\n";
    }
    elsif ($? & 127) {
        die sprintf("Command '%s' died with signal %d\n", $cmd, $? & 127);
    }
    elsif ($? >> 8 != 0) {
        die sprintf("Command '%s' failed with exit code %d\n", $cmd, $? >> 8);
    }
    return 1;
}
```

```perl
sub git_tag_exists_locally {
    my ($tag) = @_;
    my $out = qx{git tag --list $tag};
    return $out =~ /\S/ ? 1 : 0;
}

sub git_tag_exists_remotely {
    my ($tag, $remote) = @_;
    $remote //= 'origin';
    my $out = qx{git ls-remote --tags $remote $tag 2>/dev/null};
    return $out =~ /\S/ ? 1 : 0;
}
```

```perl
sub dockerhub_login_configured {
    my ($config_path) = @_;
    return 0 unless -f $config_path;
    open my $fh, '<', $config_path or return 0;
    my $json = do { local $/; <$fh> };
    close $fh;
    return $json =~ /credsStore|credHelpers/
        || $json =~ /(?:docker\.io|index\.docker\.io)/
        ? 1 : 0;
}
```
